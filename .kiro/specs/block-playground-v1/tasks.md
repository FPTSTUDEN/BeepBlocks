# Implementation Plan — Block Playground v1 (working title)

Legend:
- **[SEQ]** — done by the integrator, in order. Later tasks depend on it.
- **[PAR-x]** — belongs to parallel workstream *x*. It may run concurrently with other workstreams once Phase 0 is complete. Each workstream writes **only** inside its listed folders. `src/ir/` and `src/domains/fileExplorer/fsTypes.ts` are read-only to workstreams.
- `_Req: n.m_` points to requirements.md. `§n` points to design.md.

Environment verified: Node 22.20, pnpm 10.33, Python 3.13.5.

**Status (paused):** Phase 0 tasks 0.1–0.6 are done; `typecheck`, `lint`, `test` (100 tests) and `build` pass. `pnpm conformance` runs end to end and fails only because sim/export/composites are still stubs. Next: 0.7. It needs a git repo to tag `contract-v1`, and the user's go-ahead to create the repo and commit.

## Phase 0 — Scaffold and Contract [SEQ]

- [x] 0.1 Project scaffold
  - pnpm (10.33, pinned via `packageManager`). Vite 8 + React 19 + TypeScript 6.0 (strict; 6.0 rather than 7 because typescript-eslint requires < 6.1). Blockly 12.5 (keyboard-navigation 3.x requires ^12.3). All versions exact.
  - Scripts: `dev`, `build`, `test`, `lint`, `typecheck`, `conformance`, `test:py`.
  - Create the folder skeleton from §3 with an `index.ts` stub in each module.
  - ESLint `no-restricted-imports` rules that enforce the §3 module boundaries.
  - _Req: 13.1, 13.2, 13.6_

- [x] 0.2 IR contract (`src/ir/`)
  - `types.ts`: every type from §4.1, including the int/float literal encoding.
  - `ops.ts`: `OpSignature` plus the full registry of §5.2 and §5.3 ops, with types, `destructive`, `counter`, and `label`.
  - `composites.ts`: `CompositeStmt`, `CompositeDef`, `DesugarCtx`, `FieldSchema`, and the 4 composite *schemas* (fields, inputs, bodies, binds). Desugar bodies are stubs.
  - `errors.ts`: `ErrorCode` union, `RuntimeError`, `ValidationError`.
  - `ids.ts`: derived-ID helpers and the `resolveToExisting(id, existingIds)` used for highlighting (§4.4).
  - `serialize.ts`: JSON round trip with the version check.
  - _Req: 1.1, 1.2, 1.5, 1.6_

- [x] 0.3 Validator and typechecker (`src/ir/validate.ts`)
  - Structural checks, plus all scoping and typing rules from §4.3, the identifier rules, and the return-on-all-paths check.
  - Composites are typechecked by their schema, with bound names visible in inputs/bodies.
  - Regex-subset check (§5.4) and template-syntax check for the rename composite.
  - Plain-language messages that carry `nodeId`.
  - Unit tests: one passing and one failing case for every rule.
  - _Req: 1.7, 3.4_

- [x] 0.4 Domain contracts
  - `src/domains/fileExplorer/fsTypes.ts`: the types from §7.1.
  - `src/sim/types.ts`: `Value`, `Snapshot`, `Action`, `Timeline`, `OutputLine`, and the worker message types (§7.2, §7.3). They are exported as contract types and are read-only to Playground and Export.
  - `src/domains/theme.ts`: the `DomainTheme` interface (§10.1).
  - _Req: 6.2, 11.1_

- [x] 0.5 Conformance runner skeleton (`conformance/`)
  - `run.ts`: the full pipeline from §11 (materialize tree, run Python, read back the tree, diff, report). It calls `simulate` and `exportPython` through their module entry points, which are stubs at this point.
  - Seed fixtures: `basic-arith-print`, `mkdir-move`, and `rename-collision-error`, each with an `expected.json`.
  - `coverage.ts` skeleton that reports which ops, error codes, and composite variants are uncovered.
  - _Req: 10.1–10.4_

- [x] 0.6 Mock timeline fixture for UI work
  - `src/playground/__mocks__/timelines.ts`: hand-written `Timeline` objects for a rename run, a sort-into-folders run, a bisect run (with hints), and an error run. Playground builds against these and doesn't need the simulator.

- [ ] 0.7 Checkpoint: `pnpm typecheck`, `lint`, and `test` all pass. Freeze the contract, tag it `contract-v1`, and announce to the workstreams.

## Phase 1 — Parallel Workstreams

### Workstream A — Simulator [PAR-A]
Writes only in: `src/sim/`, `src/domains/fileExplorer/fs.ts`, `src/domains/fileExplorer/scenarios/`

- [ ] A.1 Python value semantics (`sim/pyvalues.ts`)
  - int/float arithmetic, `/ // %` floor semantics, `DIVISION_BY_ZERO`, `INT_OVERFLOW`.
  - Comparison and equality per §4.3/§5.1, including case-insensitive path equality.
  - `formatPyFloat` (Python `repr`) and `pyStr`. Test them against a table generated by running Python on 200+ values. The table generator script is committed.
  - _Req: 6.6_

- [ ] A.2 Sandbox FS model (`domains/fileExplorer/fs.ts`)
  - Immutable tree with structural sharing, path resolution, and the sort order of §5.3.
  - Name rules (Windows-strict) and case-insensitive uniqueness.
  - Every FS op from §5.3 with every error path, plus the simulation clock and the content/binary model.
  - Unit tests for each op × each error.
  - _Req: 5.1, 5.2, 6.3_

- [ ] A.3 Interpreter (`sim/interpreter.ts`)
  - Generator-based execution of primitive IR.
  - Scopes and frames, function calls and recursion (limit 200), `forEach` evaluating its list once.
  - Snapshot emission points (§7.2), counters, action log lines in the exact §7.4 format, and output lines.
  - Step limit, plus error capture into a final `error` snapshot.
  - Rejects composites. It expects desugared IR.
  - Determinism test: running twice gives deep-equal timelines.
  - _Req: 6.1–6.6_

- [ ] A.4 General op implementations (`sim/ops/`), covering every non-FS op in the registry, including the regex subset translation (`u` flag, `\1` → `$1`). Add an op completeness test against `ir/ops.ts`.

- [ ] A.5 Web Worker (`sim/worker.ts`, `sim/client.ts`)
  - The protocol from §7.2.
  - A `simulate(program, fs, opts): Promise<Timeline>` client that handles worker crashes.
  - A synchronous `simulateSync` for tests and conformance.
  - _Req: 6.7_

- [ ] A.6 Built-in scenarios (`scenarios/*.json`), each loadable and validated:
  - `messy-downloads`: mixed extensions, for sort-by-type.
  - `camera-photos`: `IMG_0001.JPG`… with mixed case, plus a few non-photos, for rename-by-pattern.
  - `project-tree`: nested folders with `.tmp`/`.log`/large files, for find-and-act.
  - `nightly-logs`: 64 dated logs where content flips from `status: OK` to `ERROR` at a known day, for bisect.
  - _Req: 5.3_

### Workstream B — Python Exporter [PAR-B]
Writes only in: `src/export/`

- [ ] B.1 Python runtime (`export/python/runtime.py`)
  - `_BPError` and `_BPPath` (case-insensitive equality, POSIX `str`).
  - `_RealFS` with explicit precondition checks, `utf-8` + `newline=""` I/O, int mtimes, and the §5.3 sort order and name rules.
  - `_PlanFS` dry-run overlay (§8.3).
  - Action log printing (§7.4), and helpers for wildcard, regex subset (`re.ASCII`), `\1` replacement, list get with bounds check, and pad/date formatting.
  - `_bp_entry` with argparse, root validation, `--apply`, and error exit codes.
  - _Req: 9.1–9.3_

- [ ] B.2 Runtime tests (`export/python/test_runtime.py`, run via `pnpm test:py`)
  - Every op × every error on a real temp dir, for both `_RealFS` and `_PlanFS`.
  - Assert that `_PlanFS` never modifies disk.

- [ ] B.3 Emitter (`export/python/emit.ts`)
  - Desugared IR → Python source per §8.2: idiomatic ops where the semantics match, runtime helpers otherwise, `at=` node IDs, block comments, `main(fs)` plus top-level `def`s, and the 4-space formatter.
  - Includes an op completeness test against `ir/ops.ts`.
  - _Req: 9.1, 9.5_

- [ ] B.4 Header generator
  - Plain-language "What it does", built from op and composite labels.
  - A destructive-ops warning section listing block IDs.
  - How-to-run instructions with dry-run and `--apply` examples, plus the partial-failure warning.
  - _Req: 9.4, 9.6_

- [ ] B.5 Public API `exportPython(program /* undesugared */): { ok: true; source: string } | { ok: false; errors }`
  - It validates, desugars through an injected `desugarProgram` (B must not import composites), and emits.
  - Golden-file tests for 6 programs.
  - _Req: 9.8_

### Workstream C — Composites [PAR-C]
Writes only in: `src/composites/`

- [ ] C.1 `DesugarCtx` with deterministic `freshName` (scope-aware) and `id(local)`. `desugarProgram`, innermost-first, pure.
- [ ] C.2 Template parser for `{name} {ext} {n} {n:3} {date} {{ }}` → concatenation IR. _Req: 2.4_
- [ ] C.3 `renameByPattern` desugaring (§6.2). _Req: 2.1, 2.2_
- [ ] C.4 `sortByType` desugaring, with the extension and category tables. _Req: 2.1, 2.2_
- [ ] C.5 `findAndAct` desugaring with every criterion and action combination, including the parent ≠ destination guard. _Req: 2.1, 2.2_
- [ ] C.6 `findFirst` (bisect) desugaring, with `VarHint`s on `low`/`mid`/`high` and the bound `candidate`/`match`. _Req: 2.1, 2.2_
- [ ] C.7 Tests
  - Golden desugared IR for each composite and variant.
  - Desugared output passes the validator.
  - Hygiene test: no collision with user variables named `n`, `items`, `low`.
  - Determinism test.
  - _Req: 2.3_

### Workstream D — Block Editor [PAR-D]
Writes only in: `src/editor/`

- [ ] D.1 Block definitions generated from the `ir/ops.ts` signatures plus a label table. Add hand-written blocks for statements, expressions, functions, and the 4 composites, with typed `check`s and plain-language labels. _Req: 3.1, 3.5_
- [ ] D.2 Toolbox in the §9 category order, and a Blockly theme driven by CSS variables. _Req: 3.2, 11.3_
- [ ] D.3 `wsToIr` (custom traversal, block ID = node ID, a warning for disconnected stacks) and `irToWs(program, layout)`. Add round-trip tests on every node kind. _Req: 3.1, 3.3_
- [ ] D.4 Live validation: debounced at 300 ms, warning icons, and plain-language messages per block. _Req: 3.3, 3.4_
- [ ] D.5 Expand action
  - Context menu item on composites. It desugars via the injected `desugarOne`, builds blocks with the derived IDs, and splices them in place inside one event group.
  - Test that behavior is equal before and after (compare the desugared IR).
  - _Req: 4.1–4.5_
- [ ] D.6 Editor API for the app
  - `<BlockEditor program layout onChange highlightIds markedIds readOnly />`.
  - Undo/redo (Blockly's built-in) and keyboard navigation plugin enabled.
  - _Req: 3.6, 13.4_

### Workstream E — Playground UI [PAR-E]
Writes only in: `src/playground/`
Builds against `__mocks__/timelines.ts`.

- [ ] E.1 Explorer view: folder tree plus a file list (icon, name, human size, UTC date), keyboard navigable. _Req: 7.1, 13.4_
- [ ] E.2 Diff states (created / renamed / moved / modified / deleted), each with an icon and text label, derived from `action` and the previous snapshot. _Req: 7.3, 13.5_
- [ ] E.3 Variable tags and the position gutter
  - Path tags.
  - `VarHint` index tags, including the "end" marker.
  - 0-based position gutter when a list is being shown.
  - Sorting by `sortBy` during bisect.
  - _Req: 7.4_
- [ ] E.4 Panels: Variables (name/type/value, "(missing)" paths), Counters (steps/reads/file changes/comparisons/list size), and Output (print + action lines). _Req: 7.5, 7.6_
- [ ] E.5 Timeline controls
  - Run/Pause/Step back/Step forward/Reset, a scrubber, and a speed selector.
  - Keyboard shortcuts, the stale overlay, and the error banner.
  - _Req: 8.1–8.4, 13.4_
- [ ] E.6 Click-to-trace: clicking an item emits the node IDs that touched its path. _Req: 7.7_
- [ ] E.7 Scenario editor mode: add, rename, and delete items, edit size/date/content, with name rules applied via `fsTypes`-level validation helpers. Changes are emitted as a new `SandboxFS`. _Req: 5.4, 5.5_
- [ ] E.8 Component tests for controls, tag placement (including the end marker), and diff labels.

## Phase 2 — Integration [SEQ]

- [ ] 2.1 App store (`src/app/store.ts`, Zustand)
  - Holds the project, the current timeline and index, stale flag, playback state, and settings.
  - Injects `desugarProgram`/`desugarOne` into the editor and exporter.

- [ ] 2.2 App shell
  - Editor | Playground split, top bar (title, scenario picker, Run, Export, settings), and the timeline bar.

  - Click-to-trace → editor highlight.
  - _Req: 7.2, 7.7_

- [ ] 2.3 Export dialog: script preview, download `.py`, copy to clipboard, and the validation error list when the program is invalid. _Req: 9.7, 9.8_

- [ ] 2.4 Persistence
  - Autosave to `localStorage`.
  - Import/export of `.bpproj.json` with full validation before replacing anything.
  - _Req: 12.1–12.3_

- [ ] 2.5 Visual themes
  - Light and dark presets plus an accent picker with automatic contrast-safe foreground.
  - Persisted in `bp.settings`.
  - _Req: 11.3, 11.4_

- [ ] 2.6 Full conformance fixture set
  - Fill every gap reported by `coverage.ts`: all ops, all error codes, and every composite × field variant.

  - _Req: 10.1_

- [ ] 2.7 Run conformance and fix drift. Fixes go into the owning module. Contract changes are documented in design.md. _Req: 10.2, 10.3_

- [ ] 2.8 Checkpoint: `build`, `lint`, `typecheck`, `test`, `test:py`, and `conformance` all green.
